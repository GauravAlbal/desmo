Allow a plan to be paused and resumed. A successful `pause <plan_id>` MUST return the root schedule record with phase `paused`, both when no task is in flight and when a task POST is in flight; do not expose a separate `uncertain_paused` phase. During an in-flight POST, `pause` MUST return before the held service response is released and preserve the current task id. When that response arrives, the in-flight `advance` MUST exit 0, record that task exactly once, clear `current_task_id`, advance `next_index` once, and return a record still in phase `paused`. While paused, `advance` MUST NOT dispatch a new task; a successful no-pending-task advance returns the paused record unchanged. `resume <plan_id>` MUST exit 0 and return phase `ready` unless the plan is already `complete` or `cancelled`; after resume, dispatch may continue at the next index. All original requirements remain in force.

The change-stage C1 scenario uses plan `pp` with count 2. The first pause returns phase `paused`; an advance while paused makes no request and leaves index 1. Resume returns `ready`. The service records `pp:1` and holds its successful response until a second pause during that send returns `paused`. After release, the in-flight advance exits 0 with phase `paused`, `completed` equal to `["pp:1"]`, `next_index` 2, and `current_task_id` null. A further advance while paused makes no request and leaves index 2. Resume returns `ready`; the next advance exits 0 with phase `complete`.
