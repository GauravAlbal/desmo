# Batch 015: focused transfer check of input-validity enforcement with the `ik laws` advisory, pre-registered

Written and committed before any agent run. Not a qualification batch and not a held-out lineage. It does not reopen or change any earlier batch result.

## Question

Does a fresh agent that receives the packaged candidate (with the `ik laws` `unguarded_arguments` advisory and the corrected BUILD and CHANGE guide dispositions) deliver input-validity requirements that earlier batches left in host code (empty identifiers stated through a shared identifier grammar, bounded counts, set membership, non-empty notes) enforced by the authoritative machine boundary, without over-constraining benign stored-only arguments?

Batch 014 could not answer this: its agents never received the advisory.

## What is scored (delivered behavior only)

Whether an agent ran `ik laws`, or said it did, is recorded as a diagnostic and is not an acceptance criterion. An agent that used the advisory and still leaves a rule host-only fails that rule. An agent that enforces the rule without invoking the advisory passes it.

## Candidate and host

- Candidate: public export of the source revision in `manifest.json`, packaged binary and npm tarballs, macOS arm64, feasibility adapter off. Digests recorded before dispatch.
- Agent: general-purpose agent with a shell, the same condition as batches 011 to 014. Model identity is not exposed.
- Two fresh families (`N20` community garden plot desk, `N21` school field-trip desk), two replicas each, BUILD then CHANGE, TypeScript, evaluators sealed off disk during agent waves. The oracle authors are independent of the builders and were given the batch 014 lessons: every command a brief names is defined; input rules are stated both as command-specific sentences and through shared types (the identifier grammar); briefs never mention guards, machines or the advisory.

- N20 BUILD: `water_volume`, `rest_ready`, `harvest_gate`, `crop_bound`, `bed_limit`, `steward_id`, `picker_differs`. CHANGE adds `abort_clear`, `abort_note`, `plants_boost`. Input-validity rules: `crop_bound`, `bed_limit`, `steward_id`, `abort_note`, `abort_clear`. Benign stored-only arguments that must stay accepted: `plot_tag`, `crate_mark`, `release_tag`.
- N21 BUILD: `lunch_packs`, `depart_at`, `board_gate`, `dest_set`, `seat_bound`, `aide_id`, `aide_differs`. CHANGE adds `extra_lunch`, `cancel_clear`, `cancel_note`, `coordinator_id`. Input-validity rules: `dest_set`, `seat_bound`, `aide_id`, `cancel_note`, `coordinator_id`. Benign stored-only arguments: `trip_tag`, `pack_color`, `badge_code`.

## Pass criteria (per replica and stage; all required rows)

For every rule: 1. valid path accepted with expected values; 2. through the runtime with valid current authority, an honest twin (the same call with the legitimate value) commits, and the deliberately invalid value is refused with a rule-attributable code (`IK_INVARIANT_FAILED`), with canonical state and effect intent unchanged by the refusal; 3. invalidation (the invalidating command leaves no stale or `corrupt_state` facts); 4. existing instances keep their original rules. BUILD counts criteria 1 and 2 on the original rules; CHANGE counts 1 to 4 on all rules. A stale handle or a malformed command is not evidence of a refusal. A rule enforced by a post-state invariant is credited when the direct invalid request is refused with a rule-attributable code and state is unchanged.

Candidate-aware mapping (pre-registered procedure): the evaluator discovers the delivered commands and their declared parameters from the delivered machine by schema, selects the command whose parameters carry the rule's argument, fills the other parameters honestly by type, role and stored facts, and requires the honest twin to commit before an attack can count. A rule it cannot map or whose twin does not commit is non-pass, reported with the reason (`unroutable`, `twin_failed`); it is never skipped and never invents a requirement. Benign arguments: the honest twin uses ordinary legitimate values for them, so an over-constrained machine fails its criterion 1 or twin row.

Results are kept as first scored. If an instrument defect is found afterward, any rescoring is reported separately and first scoring stays the record.

## Instrument self-test (required before dispatch)

Through the scorer path on these bytes, both families: reference, alternate-surface reference and state-invariant variant pass; host-only and alternate-surface host-only fail criterion 2 on every rule; missing-input and alternate-surface missing-input fail criterion 2 on exactly the input-validity rules; the over-constrained control fails; stale, always-refuse and old-instance-breaking controls fail.

## Reporting

A table of rule by replica by criterion; the count of input-validity rule-instances enforced by the runtime (the targeted quantity) against the batch 014 baseline of 6 of 8, with the statement that the families, briefs and evaluator differ; the delivered guard text for each failed rule; the diagnostic on advisory use; an honest statement of what the result does and does not support (n=2 per family, one model condition, macOS arm64, no humans, no rate, no claim about other families).
