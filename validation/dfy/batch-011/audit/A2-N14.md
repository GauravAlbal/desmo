## Verdict (short)

All four apps persist intake/verify/fill/claim/cash-pay/pickup through `invariant_kernel.Kernel` `create_with` / `aggregate.command`. Claim ids are saved in the runtime **before** POST. Lost HTTP replies stay `claim:"saved"` + `service_unavailable`; later `claim` / `reconcile` adopt by GET using the saved id. Change replicas keep v1 loadable, route with `aggregate.owner`, refuse `rush` on v1 as `legacy_rx`, and keep uncapped v1 hold. No JSON overlay, usage, or cache file is a second store.

They do **not** treat the runtime as the only lifecycle/amount authority:

- Remaining quantity, pickup deadline, rush deadline, refill restore, and (r2) claim snapshot amounts are computed in the host and passed as command args. Machine `then` writes those args.
- r1 `bind` is legal from `intake`, so `already_bound` is host-only.
- r1 `record_effect_outcome` and `mark_accepted` are two commits; r2 is the same split.
- r2 `reconcile` always contacts the provider, so an already-accepted/cash lot becomes `service_unavailable` if the service is down. r1 skips GET once locally terminal.

CHANGE.md's old-instance policy is honored in both change replicas. READMEs do not claim the new rush/cap rules apply to existing instances. No sidecar-vs-migrator guide clash.

## 1. Named writer paths

### r1/build — runtime facts, host-computed remaining/deadline

Named CLI writers (`intake`, `verify`, `fill`, `claim`, `cash-pay`, `pickup`, `reconcile`) go through `Kernel` + `machine.create_with` / `agg.command` (`rx_desk.py:291-307`, `349`, `380-391`, `504-514`, `565-575`, `595-638`, `700`). Store is only `ikaros.sqlite`. `status` / `notice` do not write. Empty `status` does not create a store (reproduced: only `unrelated.txt` remained).

`save_insurer` / `save_cash` are the kernel effect planners (`rx_desk.ik.toml:50-64`; host `504-514`, `565-575`): `effect.id` = application claim id, then POST. `mark_accepted` / `mark_rejected` / `mark_cash` commit local claim after the provider body.

Host `if agg.state != ...` branches decide BRIEF error codes before the command. Fill remaining, deadline, and `amount_cents` are computed in the host and passed as args (`353-391`).

### r1/change — owner routing, host hold-cap/rush arithmetic

Owner routing: probe `kernel.show` through v2 then v1, then `_route_machine` uses `machine.identity == probe.owner` (`235-256`). New creates `create_with` on v2 (`313-329`). Reproduced: a store written by r1/build `./run` is shown as `held` / `edition:"v1"` by the change program; `rush` is `legacy_rx` with no mutation; v1 fill through the change binary stays `pickup_deadline_ms=172800000`.

Hold cap and rush target are host `min(...)` (`400-403`, `779-794`). v2 `rush` has a machine `when` that refuses an extension (`rx_desk_v2.ik.toml:51-56`). v2 fill still takes host `pickup_deadline_ms`.

### r2/build — runtime facts, weaker machine guards

Same Kernel/`command` pattern (`desk.py` `create_with` `325`, `fill` `386-393`, `save_insurer` `504-515`, `pickup` `569-597`). Store `desk.sqlite`. Empty `status` does not create a store (reproduced).

`save_insurer` `when = "claim == 'none'"` only (`rx_desk.ik.toml:49-55`). Units/amount/effect_id are host args with no `$units == held_units` check. `adopt_*` `when` allows already-terminal claim and does not constrain `$claim_st` (`65-84`). Pickup outcomes take host `remain_after` / `refills_after` / `qty_restore` (`86-95`).

First `claim` after save always GETs, then POSTs (`408-453`). `CRASH_AT=after-claim-saved-before-request` fires after that GET, before POST.

### r2/change — owner routing, rush with no machine `when`

Owner routing: show through v2, then `_route(m1, m2, agg)` on `agg.owner` and re-`show` on the owner definition (`102-109`, `801-809`). New creates use v2 (`341-342`). Reproduced: build-program v1 store is `edition:"v1"`; `rush` is `legacy_rx`; change-program fill of a verified v1 lot is uncapped.

v2 `rush` is `then = { pickup_deadline_ms = "$deadline", rush_ms = "$rush_at" }` with **no `when`** (`rx_desk_v2.ik.toml:97-101`). Host `min(current, NOW_MS+3600000)` is the only non-extension rule (`442-457`).

## 2. Duplicate authorities / shadow state

No replica writes a JSON overlay, usage, ext, or cache file that `status` reads. Durable lifecycle is sqlite-only (reproduced: change-stage STATE_DIR after v1 claim/pickup contained only `ikaros.sqlite`/`desk.sqlite` plus the pre-existing unrelated file).

### F1. Host-computed remaining, deadline, rush, refill restore (high, application)

**Where:** r1 fill `rx_desk.py:376-391` (`remaining_qty=new_rem`, `pickup_deadline_ms=now+hold_ms`); pickup_ok `617-638` (host `qty` / `refills-1`); r1/change fill cap `400-403`; rush `779-794`. r2 fill `desk.py:384-393` (`remain_after`, `deadline`); pickup `565-597`; r2/change fill cap `401-405`; rush `442-457`. Machines: r1 `fill` `then remaining_qty = "$remaining_qty"` (`rx_desk.ik.toml:43-48`); r2 `fill` `then remaining_qty = "$remain_after"` (`rx_desk.ik.toml:42-47`); r2 v2 `rush` unrestricted (`rx_desk_v2.ik.toml:97-101`).

**Cause:** the machine stores host arithmetic. `when` on fill checks `$units <= remaining_qty` (fact) but then overwrites remaining with the host arg, which need not equal `remaining_qty - units`. Pickup restore and v2 24h cap are not machine laws. Brownfield guidance: do not keep the host branch as a second authority (`docs/brownfield-migration.md`; `skills/ikaros/build.md` step 2).

**Repro:** honest CLI is correct (v2 fill at `hold_ms=172800000` produced deadline `86400000` and `pickup_lapsed` at `NOW_MS=86400001`; v1 same hold stayed `unpaid` at that clock). The bypass is a one-argument edit (section 8), not a second file.

**Class:** application defect. BRIEF requires `NOW_MS` in the host; it does not require the host to be the amount authority.

### F2. r1 `already_bound` is host-only (medium, application)

**Where:** host `rx_desk.py:274-275` (build) / `296-297` (change). Machine `commands.bind` `from = ["intake"]` `to = "intake"` (`machines/rx_desk.ik.toml:31-35` and v2 `32-36`).

**Cause:** after the first bind, state is `intake`. A second `bind` is still legal on the machine and would overwrite `rx_id` / qty. The host returns `already_bound` without calling `command`. r2 intake is `from = ["empty"]`, so the machine itself refuses a second intake.

**Repro:** second `intake` is `already_bound` on the honest path (r1 tests and scratch). Removing the host check would still be a runtime commit.

**Class:** application defect.

### F3. r1 `status` hides `pickup_deadline_ms == 0` (low, application)

**Where:** `snap_from` `rx_desk.py:109` / change `124`: `None if not deadline else deadline`.

**Cause:** `0` is falsy. Fill with `hold_ms=0` at `NOW_MS=0` returns `pickup_deadline_ms:0` then `status` reports `null`. r2 uses `deadline < 0` and shows `0`.

**Repro:** `/tmp/InspectN14-scratch/r1-hold0` — fill body `pickup_deadline_ms: 0`, status `pickup_deadline_ms: None`. Pickup still uses fact `0` (`or 0`).

**Class:** application defect.

## 3. Partial-commit seams

### F4. Effect record and claim mark are two kernel commits (medium, application)

**Where:** r1 `record_and_mark` `405-415` (change `430-440`): `record_effect_outcome` then `mark_accepted` / `mark_rejected` / `mark_cash`. r2 `_record_if_pending` then `_adopt` (`desk.py:263-290`, `428-429`, `471-473`). No `transaction()`.

**Cause:** `CRASH_AT=after-accept-before-record` is before both; `after-record-before-exit` is after both. A kill between the two leaves kernel effect recorded and `claim` still `"saved"`. Status (claim fact) and effect journal disagree until a later GET/adopt. Recoverable on retry; not atomic.

**Repro:** not injected (would need a third crash label). Code path is sequential two `command`/`record` calls with no wrapping transaction.

**Class:** application defect.

### F5. r1 crash-before-request is before POST; r2 crash-before-request is after GET (low, application)

**Where:** r1 `post_claim` `434-436`. r2 `_submit_saved` GET `411-412` then `if crash: _crash(...)` then POST `450-453` (change `473-515`).

**Cause:** BRIEF label is “after saving a claim id and claim snapshot, before sending a request.” r2 has already sent GET.

**Repro:** r2 posts count `3→3` across `CRASH_AT=after-claim-saved-before-request`; status `claim:"saved"`; no new POST. r1 SIGKILL `-9`, status `saved`, reconcile `lookup:"not_sent"`.

**Class:** application defect vs BRIEF letter. GET 404 does not create an accepted effect, so R8 still held on this stub.

## 4. Operation / effect binding

Claim id is created in the host (`uuid` r1, `secrets.token_hex` r2), passed into `save_insurer` / `save_cash`, and used as `effect.id` / `idempotency_key`. POST body uses that same snapshot. A later `claim` with `claim=="saved"` does not allocate a replacement id (r1 `519-532`; r2 `490-491`).

First r1 `claim` POSTs without GET (BRIEF “then posts once”). Retry GETs, 404 POSTs once with the saved id. r2 always GETs first, including the first claim.

A second HTTP POST for the same saved id is possible after GET 404. BRIEF allows that. The kernel effect is planned once at save; the host may POST again for that id. No replica calls `Machine.lookup_operation`. Lost stdout is recovered by `show`/`status` plus provider GET, which matches BRIEF R8–R12; it is not kernel operation-identity recovery (`docs/client-recovery.md`).

r2 `save_insurer` does not require `effect_id == claim_id` or `units == held_units`. Host binds them equal today.

## 5. Unknown outcomes

Incomplete JSON, transport/timeout, and HTTP 5xx return `service_unavailable` and leave `claim:"saved"` (r1 `437-440`; r2 `413-416`, `454-459`). Reproduced: r2 `error_status=503` → `{error:service_unavailable}` and `status_claim=saved`. Dropped accepted reply is the stub `drop_reply` path; tests cover it; not re-run here as a full drop, but 5xx/crash paths were.

Mismatching 200 is `lookup_conflict` without write (r1 `445-446`). r1 cash + provider `rejected` is `lookup_conflict` (`454-455`). r2 cash + `rejected` takes `if outcome == "rejected": adopt_rejected` first (`_adopt` `285-290` / change `301-305`) and would mark `claim:"rejected"` instead of `lookup_conflict`. The shipped stub never rejects `payor:"cash"` (only `DENYALL`+`insurer`), so this is latent on the supplied provider.

### F6. r2 `reconcile` (and cash/accepted lookup) requires a live provider even when local claim is terminal (high, application)

**Where:** r2 `do_reconcile` `610-663` (change `672-725`) always GET. r1 `669-674` (change `694-699`) returns local success when `claim in (accepted, rejected, cash)` without GET.

**Cause:** transport failure on GET is `service_unavailable` even if sqlite already has `accepted`/`cash`.

**Repro:** r2 after accepted claim, `SERVICE_URL=http://127.0.0.1:1` `reconcile` → `service_unavailable`. Same lot `claim` → success no-op. r1 `reconcile` on accepted/cash with dead service → exit 0, `lookup:"accepted"`. r2 cash + dead service `reconcile` → `service_unavailable`.

**Class:** application defect. Repeat `claim` after accepted is the BRIEF no-op; reconcile is specified as a lookup, but fabricating `service_unavailable` for a fully committed local cash/accepted record is an unknown-outcome mishandle.

r1 cash reconcile (live or dead) returns `lookup:"accepted"` while `claim:"cash"` (reproduced). BRIEF lookup labels are `accepted`/`rejected`/`not_sent`; cash has no lookup name. Misleading but non-mutating.

## 6. Persisted owner routing / CHANGE.md old-instance policy

Both change replicas:

- Keep v1 toml loadable.
- Route with `aggregate.owner` vs `machine.identity` (r1 `235-239`; r2 `102-109`).
- Create new intakes on v2 with `edition:"v2"` (reproduced).
- Probe/`show` through v2 first, then reopen the owner definition (r1 `249-256`; r2 `801-809`). Guidance allows show through another loaded definition; commands use the routed machine. Owner probe after a build-program instance: `eq_v1 True`, `eq_v2 False`, `MachineIdentity('rx_desk', version=1)`.

Old-instance policy (CHANGE.md):

| Rule | r1/change | r2/change |
|---|---|---|
| v1 `rush` → `legacy_rx`, no mutation | reproduced | reproduced |
| v1 fill uncapped `NOW+hold_ms` | fill via change of a verified v1 lot: deadline `172800000`; pickup at `86400001` is `unpaid` | same |
| v2 fill cap 86400000 | fill deadline `86400000`; pickup at `86400001` is `pickup_lapsed` | same |
| v1 `rush_ms` stays null | status `rush_ms: null` | same |

`legacy_rx` is decided from `edition` (and r1 also `machine.identity.version == 1`) after `rx_mismatch`, before `not_held` (`r1/change:773-778`; `r2/change:435-441`). Matches CHANGE.md rows 24–25.

Fallback if `identity != owner`: r1 `_route_machine` returns `machines[2]` (`240`); r2 `_route` returns `m2` (`109`). On this runtime, identity matched, so the fallback did not fire. If it did, a v1 aggregate would be commanded through v2 (`IK_MACHINE_MISMATCH` or a new-machine command). Latent.

No replica migrates stored `(machine_id, version, spec_hash)` or adds a sidecar for rush/cap.

## 7. Hollow paths

CLI commands that succeed do the work on the honest path (intake binds, fill deducts, claim POSTs once, pickup restores/lapses). Repeat `verify` in `verified` is a specified no-op (r1 skips `command`; r2 issues `verify` which is legal `from`). Repeat `claim` after accepted/rejected/cash is a specified no-op without POST (r1 also issues `claim_idle`; r2 returns facts only).

`notice` ignores well-formed files and does not POST (r1 returns `{ignored:true}`; r2 returns a status snapshot). Held state unchanged in tests.

Machine rules: r1 `claim_idle` is only the repeat-claim no-op. r2 has no equivalent. r2 `verify` has no `when` on `rx_id` (host-only). r2 `adopt_*` `$claim_st` is unchecked.

Tests are not empty: r1/r2 exercise crash labels, DENYALL/cash, unpaid/lapse, foreign files, corrupt sqlite. Weak spots:

- r1/change `test_legacy_v1_continuity` shells out to `/tmp/rx_desk_prechange_N14r1/run` (present on this machine; not in the project).
- r2 several helpers ignore intake/verify return codes and only assert the later error.
- Fill-from-lapsed `already_moved` is untested (reproduced; BRIEF does not name that code for `fill`).
- r2 cash+`rejected` adopt path untested (stub cannot produce it).

## 8. Single edit that keeps the app working while bypassing the runtime

**All replicas (amount/deadline):** in `cmd_fill` / `do_fill`, pass `remaining_qty=0` or `remain_after=0` (and/or `deadline=NOW_MS` without `min(hold, 86400000)`). The machine writes the args. Status/pickup then follow the host numbers with no further Ikaros law. The CLI shape stays intact because host branches already duplicate `not_verified` / `already_held` / `bad_units`.

**r2/change rush:** in `do_rush`, pass `deadline=current+N` / `rush_at=current+N`. v2 `rush` has no `when`. r1/change cannot extend: `$pickup_deadline_ms <= pickup_deadline_ms`.

**r1 bind:** delete the `if agg is not None: already_bound` arm. Second `intake` still `create_with`/`bind` because `from=["intake"]`. r2 cannot: `from=["empty"]`.

**r2 save_insurer:** pass a different `units`/`amount_cents`/`effect_id` than `held_units`; `when` is only `claim == 'none'`.

## 10. Delivered defects a behavioral test and a store-sufficiency test would likely miss

- Host `remain_after` / `remaining_qty` / `deadline` args (F1): happy-path tests always pass the honest arithmetic. A store dump of facts after fill looks consistent. Sufficiency of sqlite facts does not see that the machine would have accepted a lie.
- r2 v2 `rush` with no `when`: tests use host `min`. Store has the rushed deadline; nothing shows the machine would accept an extension.
- r1 `bind` from `intake` (F2): tests never issue a second bind without the host guard.
- F4 record-then-mark split: crash labels sit outside the pair; tests never kill between them. Store after success is accepted; store after the labeled crashes is either saved or accepted, never the mixed journal/fact pair.
- r1 `pickup_deadline_ms: null` for stored `0` (F3): tests use positive `NOW_MS`/`hold_ms`.
- r1 corrupt vs `bad_time` precedence: tests cover missing both env vars (`bad_time`) and corrupt with valid env (`corrupt_state`), not corrupt sqlite **and** missing `NOW_MS`. Reproduced: r1 → `bad_time`; r2 → `corrupt_state`. BRIEF row 1 is corrupt_state.
- r2 `reconcile` on a terminal lot with a down provider (F6): tests reconcile while the stub is up, or only after `saved`. Repeat `claim` after accepted with a dead URL still succeeds, so a claim-only suite misses it.
- r1/r2 cash reconcile `lookup:"accepted"`: tests check accepted lookup, not cash.
- `lookup_operation` unused: lost-stdout cases in the suite use `status` after the process dies at a labeled crash, not an operation-id query.
- Fill from `lapsed` → `already_moved`: not in the suite.
