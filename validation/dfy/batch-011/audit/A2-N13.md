## Verdict (short)

Both replicas persist lifecycle facts in one Ikaros sqlite store (`ill-desk.sqlite`) and plan the lender HTTP effect on `save_attempt`. There is no JSON overlay / aux file acting as a second store. Change replicas keep v1 loadable and route `show`/commands via `aggregate.owner`. The new overdue-checkin rule and the 7-vs-14-day span are **host branches**, not machine rules: `checkin` on v2 has no `when` guard, so a direct runtime `checkin` returns an overdue loan without `place-recall`. Neither change tree delivered a handoff. `lookupOperation` is unused; only `file` in r1 binds a caller operation id.

## 1. Named writer paths

Durable lifecycle writes go through `@ikaros/runtime` (`createWith`, `command`/`execute`, `recordEffectOutcome`). Owned store name is `ill-desk.sqlite`. No host JSON/cache/usage file is an additional authority for amounts or status.

Host **does** decide several lifecycle refusals and amounts before/instead of the machine:

| Decision | Where |
|---|---|
| Loan span (14d vs 7d) | Host computes `loan_until_ms` and passes it as checkout args. Machines accept any int. |
| `recall_required` | Host `if` only (change). v2 `checkin` is unguarded. |
| `legacy_request` | Host `isLegacy` / `identity.equals` before `place_recall`. Correct named code; not a v1 machine refusal. |
| Repeat `transmit` after accepted | r1 returns success without a runtime call (`transmit_noop` unused). r2 calls `ack_transmit`. |
| `callback` | r1 never touches the runtime. r2 calls `ignore_callback` and swallows errors. |

### r1/build

- Writers: `src/desk.js` `apply` → `agg.command` (143–155), `createWith` (263–267), `save_attempt` (412–416), `acceptLoan` (215–221).
- `callback` (237–251) parses JSON and returns `{ok:true}` with no machine command. Matches BRIEF “ignore” but is not a named writer through Ikaros.
- Status mapping `idle`→`none` (95) is host projection of the v1 initial state name.

### r1/change

Same writers plus `place_recall` (321) and dual machines (132–136, 139–144). Checkout span and overdue checkin are host `isLegacy` / `recall_placed` branches (116–123, 350–369).

### r2/build and r2/change

Writers: `agg.execute` / `createWith` / `recordEffectOutcome` in `src/desk.mjs`. `save_attempt` carries `effect` (`desk.ik.toml` 41–47). `commit_accepted` is the finish command.

## 2. Duplicate authorities / shadow state

No sidecar file for lifecycle. The duplicate authority is the **host process**:

1. **v2 `checkin` does not encode recall.** r1 `machines/ill_desk_v2.ik.toml` 71–73 and r2 `desk_v2.ik.toml` 72–74: `from = ["out"]` `to = "returned"` with no `when`. Host enforces `recall_required` at r1/change `src/desk.js` 364–367 and r2/change `src/desk.mjs` 528–530.

   Reproduced (scratch `/tmp/n13-inspect`, not the shipped tree):

   - r2/change CLI at `NOW_MS=605801001` after 7-day checkout: `{"error":"recall_required"}`, status stayed `out`.
   - Direct `v2.show("desk").execute({name:"checkin"})`: `DIRECT_CHECKIN_OK returned`; subsequent `./run status` was `status:"returned"` with `recall_placed:0`.
   - r1/change: same pair of results (`DIRECT_CHECKIN_OK returned`).

   Class: **application defect**. Severity: **high**. The clock is env (`NOW_MS`), so overdue must be supplied as a command arg if the machine is to refuse; that is still expressible (`when = '$overdue == 0 || recall_placed == 1'`). Leaving the rule only in the host makes the runtime store insufficient for the new law.

2. **Checkout span is host-only.** Machines take arbitrary `loan_until_ms`. r1/change `loanSpan` (121–123) uses `Number(agg.owner.version) === 1` (116–118), **not** `identity.equals`. r2/change uses `v1.identity.equals(agg.owner)` (123–128) for the span and `route()` (116–120) for commands. A wrong host span still commits.

   Class: **application defect**. Severity: **medium** (r2 routing identity is sound; the amount is still not a machine law). r1 version-only `isLegacy` is a weaker owner check than `docs/machine-evolution.md` (all three identity fields).

3. **Success JSON is often reconstructed from argv/facts, not re-read.** r1/change `file` (291–292) returns the request triple even if `createWith` returned history. If persistence failed after a thrown path that is not caught, the CLI could still claim `filed` only when `createWith` returns; the HistoricalResult branch is broken (see §7).

## 3. Partial-commit seams

Intended Ikaros effect split: `save_attempt` (plans `ill.loan_request` / `ill.loan`) → host POST → `recordEffectOutcome` → `accept` / `commit_accepted`. CRASH_AT labels match BRIEF. Tests cover the three kill points and dropped reply.

Seams that remain:

1. **HTTP success then record/accept crash** is recovered by GET (R9). Observed in delivered tests. Not a defect if GET is used; both replicas GET on saved attempts.

2. **Record then accept** (docs/typescript.md: crash between record and finish leaves outcome recorded, domain still `located`/`attempt_saved`). Next `transmit`/`reconcile` GET 200 and `acceptLoan`/`adoptAccepted` skip record when `pendingIntent` is absent, then finish. Coherent.

3. **r1 records the planned payload digest as the outcome**, not the HTTP body (`acceptLoan` passes `cur.pendingIntent.payloadDigest`, r1/change `src/desk.js` 238–243; same in r1/build 215–221). Guidance: digest the response body (`docs/typescript.md` 207–219). r1 scenarios also set `outcome_digest` equal to `payload_digest` (`scenarios/happy-path.json` 9). A later record of the real body digest would `EffectConflictError`.

   Class: **application defect**. Severity: **medium**. Recovery still works because every record path uses the same planned digest.

4. **r2 first POST 200 with non-matching JSON** is `service_unavailable` (`src/desk.mjs` 308–310 build, 338–340 change), not BRIEF `lookup_conflict`. Recover GET 200 mismatch **is** `lookup_conflict` (299, 326). After a POST that the provider stored with unexpected fields, the CLI reports unavailable; a later GET may `lookup_conflict`.

   Class: **application defect**. Severity: **low**.

5. **r2 `reconcile` after the request is no longer `located`** still GET-matches then `adoptAccepted` → `commit_accepted` (change `src/desk.mjs` 562–586). On a `returned` desk this threw through to `{"error":"bad_args"}` (reproduced `/tmp/n13-inspect/state-r2c`). r1 skips accept unless `located` && `attempt_saved` (change `src/desk.js` 407–410) and still returns a transmit-shaped success object even when the desk is past `requested` — a lying projection, not a mutation.

   Class: **application defect**. Severity: **medium** (r2 maps a kernel illegal-state to `bad_args`; r1 returns `status:"requested"` while the store is not).

No crash window was found that writes a host file the runtime does not own.

## 4. Operation / effect binding

| Replica | `operationId` on mutations | `lookupOperation` |
|---|---|---|
| r1/build | only `createWith` (`src/desk.js` 266) | none |
| r1/change | only `createWith` (289) | none |
| r2/build | none | none |
| r2/change | none | none |

r1 `apply` uses `Aggregate.command(name, args)` (`client.d.ts` 113) which has **no** `operationId` parameter. r2 `execute` omits `options.operationId`, so the client generates a new id per CLI process (`client.d.ts` 115–123).

Consequences:

- A lost reply on `save_attempt` / `accept` / `recordEffectOutcome` is not reconciled by operation id. The next process `show`s current state (domain recovery). That is the negative control `docs/operation-identity.md` D9 / case 2 warns about, mitigated here by BRIEF “one process at a time.”
- **Same attempt, second HTTP POST:** first `transmit` POSTs without GET (BRIEF). Saved-attempt path GETs first; 404 POSTs the saved id once. That is the specified retry, not a replacement id. r1 never allocates a second id (`newLoanId` only when `lender != attempt_saved`). r2 id is `L.${req_id}` (build `firstTransmit` 262; change 289).
- Dropped **record** reply: r1 retries record with the same payload digest (exact outcome is a no-op per typescript.md 253). r2 retries with `bodyDigest(text)`; same body is a no-op, different body conflicts.
- r1/change HistoricalResult on `file` is a **second request with the same id** that then crashes (see §7) instead of returning history.

r2 generated `loan_req_id` can exceed the 1–64 identifier rule: `L.` + 63-char `req_id` is 65 characters. Reproduced: transmit succeeded with `loan_req_id` length 65. Class: **application defect**. Severity: **low** (example ids in BRIEF are short; the stub accepted it).

## 5. Unknown outcomes (HTTP)

Both replicas treat connection failure, abort, and HTTP 5xx as `service_unavailable` without calling `accept`/`commit_accepted`. Dropped-reply tests exist.

- r1 `httpCall` (`src/desk.js` 167–187): JSON parse failure → `service_unavailable` (incomplete response, BRIEF-correct). No fetch timeout (provider “may delay”; hang is possible).
- r2 `httpJson` (change 218–240): 15s abort → `{complete:false}` → `service_unavailable`. Unparseable body sets `json=null` and still `complete:true`.
- First-attempt 5xx does not GET (r1 426; r2 `firstTransmit` has no lookup). Matches BRIEF.
- Neither replica guesses `accepted` from a lost HTTP reply; they persist `attempt_saved` and require GET/POST recovery.

Class for missing `lookupOperation` on the **runtime** record/accept (not HTTP): **application defect**, severity **medium**, see §4. HTTP unknown handling itself is largely aligned.

## 6. Persisted owner routing (change stage)

CHANGE.md old-instance policy: `place-recall` → `legacy_request` and no mutation; checkout 14-day; overdue checkin allowed; terminal states stay terminal; saved attempts keep R8–R12.

### r1/change

- Loads v1 and v2 (132–136). `showDesk` probes `v2.show` then re-shows through `owningMachine` via `agg.owner.equals(v1.identity)` (139–154). Commands therefore run on the owner definition, not “current default.” Matches `docs/machine-evolution.md`.
- `place-recall` checks `isLegacy` **before** `not_out` (309–311): `legacy_request` wins, including cancelled/lost/returned.
- `isLegacy` is `Number(agg.owner.version) === 1` (116–118), not full identity. If `owner` is missing, it is treated as new → `place_recall` against a v1 aggregate would be a kernel error mapped to `bad_args` by `run` line 15, **not** `legacy_request`.
- New creates use `v2.createWith` (286–290).
- Tests `tests/ill.test.mjs` 387–410 exercise `OLD_PROJECT_DIR` file + post-change locate/transmit/checkout/overdue checkin (C2/C4).

### r2/change

- `route` / `isLegacy` use `identity.equals(agg.owner)` (116–124). Stronger.
- Same `legacy_request` before `not_out` (452–454). Empty desk `place-recall` is `not_out` (reproduced).
- Tests `tests/desk.test.mjs` 358–386 cover legacy file + 14-day checkout + overdue checkin without recall.

Neither change replica **shows/commands an old aggregate through the new machine** for mutations after the owner probe. `v2.show` is used only to read `owner` (documented as allowed).

Handoff statements: **none delivered** (no `Delivered:` / `not met for existing instances` outside the skill template under `.agents/` and KIT docs). CHANGE.md is the request, not a report. The code tries to **meet** C1–C5 for old instances via owner routing rather than claiming a migrator gap. There is no false “not met” claim to contradict; there is also no evidence-backed handoff as `skills/ikaros/change.md` step 12 requires.

Class for missing handoff: **application defect** (delivery). Severity: **low**.

## 7. Hollow paths / unused rules

1. **r1/change `file` HistoricalResult uses undefined `machine`.** `openMachines` returns `{kernel, v1, v2}` (132–136) but line 291 does `await machine.show(AGG)`. Reproduced in scratch: second `createWith` with the same `operationId` yields `HistoricalResult`, then `TypeError Cannot read properties of undefined (reading 'show')`. CLI maps that to `bad_args` (`run` 13–16). The correct recovery (same operation id after a lost create reply) is therefore a false `bad_args`. r1/build binds `machine` from `openMachine` and does not have this bug.

   Class: **application defect**. Severity: **high** (breaks the one path that *does* bind `operationId`).

2. **r1 `transmit_noop`** is in all three r1 tomls and never called. Repeat transmit after accepted is a host no-op (r1/change 419–423). Unused machine rule.

3. **r2 `ack_transmit`** is called on repeat transmit (change 479–481). If that command is not a kernel no-op, repeat transmit is a mutation despite BRIEF “success no-op.” Not executed against the journal in this inspection.

4. **r2 `ignore_callback`** `from` omits `returned`/`lost`/`cancelled` (`desk.ik.toml` 85–94). Host catch-all returns `{ok:true}` (change 406–411). A well-formed callback on a corrupt execute also returns success (catch does not `classify`). Class: **application defect**. Severity: **medium** (BRIEF wants ignore-without-overwrite; swallow-all also hides `corrupt_state`).

5. **r2 unknown command on an empty desk is `bad_status`.** BRIEF: unknown command is `bad_args`. Reproduced: r2/build and r2/change `./run foobar` with empty `STATE_DIR` → `{"error":"bad_status"}`. r1 correctly `bad_args`. After an aggregate exists, r2 unknown commands fall through to `bad_args` (change 589). Class: **application defect**. Severity: **medium**.

6. **r2 command handlers `catch { mapIllegal }`** (receive/checkout/checkin/cancel/place-recall) turn any kernel error, including `corrupt`, into a domain status code. Class: **application defect**. Severity: **medium**.

7. **r1 `run` / `src/main.js` classify corrupt by `msg.includes("corrupt")`** (build `run` 15; change `run` 15, `src/main.js` 14). `skills/ikaros/build.md` step 8: never by message text. Class: **application defect**. Severity: **low**.

8. **Corpora / scenarios do not witness `recall_required`.** r2/change `scenarios/recall.json` 64–75 commits `checkin` after `place_recall` with no overdue/refusal case. v2 machine would also commit checkin *without* recall (confirmed by direct execute). r2 `desk.ik.cases.json` omits `receive`, `checkin`, `cancel`, `ack_transmit`, `ignore_callback`, `declare_lost`.

9. **r1 callback** never executes a machine command; tests only assert `ok` and unchanged `status`. Fine vs BRIEF, hollow vs “every named writer through the domain API.”

## 8. Single edit that keeps the app working while bypassing the runtime

**Change replicas (strongest):** delete the host `recall_required` block (r1/change `src/desk.js` 365–367; r2/change `src/desk.mjs` 528–530). CLI overdue `checkin` then succeeds; v2 `checkin` already allows `out`→`returned`. Tests that only drive `./run` would fail; the store/machine would not.

Equivalent one-liners:

- Force `loanSpan` to `LOAN_SPAN_NEW` / `LOAN_SPAN_V2` so pre-change instances get 7 days; both checkout commands accept the args.
- r1/change: `function isLegacy(agg) { return false; }` — old instances get 7-day checkout; `place-recall` becomes a kernel error/`bad_args` instead of `legacy_request`.

**Build replicas:** make `apply`/`execute` return the input aggregate unchanged and keep returning host-built success objects (`file`/`locate`/`checkout` already return argv-derived JSON). Status would drift unless `show` is also stubbed; stubbing `showDesk`/`loadDesk` to read a JSON file next to the sqlite path would fully bypass the runtime while `./run` still prints contract-shaped objects.

**r1/change file:** the HistoricalResult line already does not use the runtime result; fixing `machine` vs `v2` is required for honest recovery, and skipping `createWith` while returning the filed object would be a one-line lie.

## 9. Handoff vs code

No change-report handoff exists in the delivered project files (`README.md` on both change replicas still describes only the v1 machine and omits `place-recall`). There is therefore **no** `'not met for existing instances'` statement to compare. Observable code **does** implement the CHANGE.md old-instance policy at the CLI (legacy refusal, 14-day span, overdue checkin without recall) except that those rules are host-enforced and therefore not true of the v2 machine (see §2). That is a mismatch between “old instances remain on original rules in the runtime” (guidance) and “CLI special-cases owner.version / identity” (delivery).

## Delivered defects a behavioral test and a store-sufficiency test would likely miss

Behavioral tests here drive `./run` and the stub. Store-sufficiency tests that only compare sqlite facts to `status` JSON would still miss:

- Host-only `recall_required` / loan span (facts after a **compliant** CLI checkout/checkin look right; the machine still allows the forbidden transition).
- `lookupOperation` absence (one process, show-based retry never hits case 2).
- r1 outcome digest = payload digest (HTTP body never compared once matchingLoan succeeded).
- r1/change `machine.show` TypeError (new `operationId` every `file`; HistoricalResult not hit).
- r2 `catch { mapIllegal }` mapping `IK_STORE_CORRUPT` to `bad_status` if `show` succeeded and `execute` failed.
- r2 callback swallow on non-illegal errors.
- r2 `loan_req_id` length > 64 with long `req_id` (BRIEF examples are short).
- r2 first-POST mismatch coded as `service_unavailable`.
- r1 `transmit_noop` unused (repeat transmit never writes; tests check JSON only).
- Corrupt classification by message text (r1).
- Dual `run` vs `src/main.js` in r1 (same bug duplicated).

A **machine-only** store-sufficiency / scenario run **would** catch unguarded v2 `checkin` (r2 `recall.json` even expects checkin to commit with no overdue predicate). It would **not** catch CLI owner-routing bugs or HTTP binding.
