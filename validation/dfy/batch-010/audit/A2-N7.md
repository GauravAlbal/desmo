## Verdict (short)

Both replicas commit pack/book/confirm through Ikaros command/effect APIs and bind the carrier POST to the saved request id. Neither uses `lookupOperation` / caller `operation_id`. Both split order creation and cancel/expire across multiple aggregates (r1: three machines + `desk-aux.json` saga; r2: two SQLite stores, no recovery). That split is the main lifecycle defect. Change-stage owner routing works on both replicas for persisted v1 packed orders. r2/change’s “packed cancel atomic” test never cancels a packed order.

The brief needs an atomic facility-hold + order-create (and cancel/expire + release). Ikaros per-aggregate commit cannot keep that atomic. `skills/ikaros/build.md` step 2 tells the builder to refuse fit and stop. Both builders shipped a host saga anyway. Topology: candidate/guide. Crash-unsafe sagas and the r1 sidecar: application.

## 2. Duplicate authorities / shadow state

### F1. r1 `desk-aux.json` is a durable host store that can diverge from the kernel

**Where:** r1/build `src/desk.mjs:94-119,165-174,255-269`; r1/change `src/desk.mjs:94-120,203-212,317-332`.

**Cause:** `writeAux` persists `{pending, freed}` beside `warehouse.sqlite`. `recover()` treats `pending.kind === "free"` as authority to release parcels **without** requiring the order to be `expired`/`cancelled`. `maybeExpire` writes that pending record *before* `expire_live`.

**Repro** (observed):

```bash
# /tmp/InspectN7-scratch/r1-aux-free-before-expire.mjs
# after a live picked order, inject:
#   desk-aux.json = {pending:{kind:"free",order_id:"o1",facility_id:"north",parcel_id:"P1"}, freed:{}}
# then ./run status o1
```

Result: order stayed `picked`; `facility-status` `held` went `1 → 0`; a second order took `P1`. Aux ended `{pending:null, freed:{o1:true}}`.

**Severity:** high. **Class:** application defect (guide: no host store deciding the same lifecycle; `docs/brownfield-migration.md`).

### F2. r1 facility.held (counter) vs parcel aggregate (occupant) vs order facts

**Where:** r1/build `machines/facility.ik.toml:21-27` (host supplies `held+1`), `machines/parcel.ik.toml`, `src/desk.mjs:176-231,233-252`.

**Cause:** Exclusivity is the parcel machine; capacity is a host-computed integer on the facility machine; the order’s `parcel_id` is a third copy. F1 already produced “order picked + parcel free”.

**Severity:** high (same family as F1). **Class:** application defect. Topology (three machines for one admission) is also a candidate/guide fit miss (`build.md` step 2).

### F3. r2 occupancy blob is host-owned meaning inside runtime facts

**Where:** r2/build `src/main.mjs:110-171,359-387`; r2/change `src/main.mjs:111-194,402-467`; `machines/facility.ik.toml:21-26` (`$expected == occupancy` only).

**Cause:** The facility machine does not know parcels. The host parses `|P1=o1|`, checks exclusivity, and CAS-es a string. That commit *is* a runtime commit, so this is not a sidecar file. It is still a host status encoding the machine cannot refute except by CAS.

**Severity:** medium. **Class:** application defect (host branch decides occupancy); candidate/guide for asking one atomic admission across facility+order.

### F4. r2 two kernel stores

**Where:** r2/build `src/main.mjs:350-357`; r2/change `src/main.mjs:379-387`.

**Cause:** `facility.ik.sqlite` and `order.ik.sqlite` cannot share a commit. Cancel/expire/create are cross-store sagas with no recover log (F6–F7).

**Severity:** high (enabler). **Class:** application defect.

## 3. Partial-commit seams

### F5. r1 `facility` create then configure — crash leaves an unconfigurable facility

**Where:** r1/build `src/desk.mjs:369-378`; r1/change `src/desk.mjs:429-438`. Machine `configure` refuses a different capacity (`machines/facility.ik.toml:18`).

**Cause:** First commit is `create` (capacity 0). Second is `configure`. No `CRASH_AT` here, but SIGKILL between them is allowed by R1. Retry with the intended capacity sees `0 !== 3` and returns `conflict`. There is no public command that can set capacity on an existing row.

**Repro** (observed): Kernel `create("north")` then `./run facility north 3` → `{"error":"conflict"}` (scratch `r1-facility-split.mjs`).

**Severity:** high. **Class:** application defect. r2 uses `createWith("open", {capacity})` and does not have this seam.

### F6. r2 cancel: order cancelled, occupancy not released; retry is a no-op

**Where:** r2/build `src/main.mjs:432-454`; r2/change `src/main.mjs:492-531`. Idempotent success at `440-441` / `500`.

**Cause:** `cancel_picked` / `cancel_packed` commits on the order store, then `releaseParcel(s)` on the facility store. Crash between them leaves a cancelled order that still holds capacity. The next `cancel` sees `cancelled` and `ok()` without releasing.

**Repro** (observed, r2/build and r2/change): after a live order, Kernel `execute({name:"cancel_picked"})` on the order store, then `./run cancel o1`. stdout `state: cancelled`, `facility-status` still `held: 1`, `./run order o2 north P1 9000` → `parcel_taken`.

**Severity:** high. **Class:** application defect.

### F7. r2 expire: same split, retry will not release

**Where:** r2/build `src/main.mjs:193-208,457-478`; r2/change `src/main.mjs:221-238,552-575`. `maybeExpire` returns early once state is no longer picked/packed.

**Repro** (observed, r2/build): Kernel `expire` with `now_ms >= deadline`, then `./run expire o1` / `status`. Order `expired`, `held` stayed 1, same parcel `parcel_taken`.

**Severity:** high. **Class:** application defect.

### F8. r2 create: hold then `createWith`; crash leaks occupancy unless the same order id is retried

**Where:** r2/build `src/main.mjs:383-406`; r2/change `src/main.mjs:442-466`. Catch path releases only if this invocation’s `hold` succeeded (`occupant !== orderId` / `heldOk`).

**Cause:** A crash after `hold` and before `createWith` leaves `|P1=o1|` with no order row. Retry of the *same* `order o1 ...` skips hold (`occupant === orderId`) and creates. A different order id sees `parcel_taken`. There is no startup recover.

**Severity:** medium (retry of the same CLI line heals; any other path does not). **Class:** application defect.

### F9. r1 create/free saga is crash-aware but the pending record is not the runtime

r1 writes `aux.pending` before the kernel steps (`cmdOrder` `405-414` / change `480-488`; `maybeExpire` before `expire_live`). That is better than r2 for *some* crashes, and worse when the sidecar commits without the matching order command (F1).

**Severity:** high when combined with F1. **Class:** application defect.

## 4. Operation / effect binding

### What holds

- First `book` from `packed` allocates one request id, commits `save_attempt` with `effect_id` / `idempotency_key` / `request_id` equal to that id, then POSTs that body. r1/build `472-524`; r1/change `584-627`; r2/build `503-524`; r2/change `600-621`.
- Machine guard `attempt_flag == 0` (r1) / `attempt_flag == 0` then `+1` (r2) prevents a second id while the attempt is open.
- Retry of `attempt_saved` GETs the saved id first; POST only on 404. r1 `508-521`; r2 `526-536`.
- `reconcile` never POSTs.

### F10. No kernel `operation_id` / `lookupOperation` on any writer

None of the four `src/*.mjs` files call `lookupOperation` or pass `operation_id` into `createWith` / `command` / `execute` / `recordEffectOutcome`. Lost stdout after a kernel commit is reconciled by `show` + host idempotency, not by `docs/client-recovery.md`.

The brief’s recovery story for *booking* is provider GET by saved request id, which they implement. The gap is kernel-commit attribution (facility configure, pack, confirm).

**Severity:** medium for kernel lost-reply; low for the carrier effect (bound to request id). **Class:** application vs guide; not a brief R7–R9 miss by itself.

### F11. r1 records effect outcome as `sha256(booking_id)`, not the HTTP body

**Where:** r1/build `src/desk.mjs:351-354`; r1/change `414-418`. r2 uses `digestText(outcomeText)` of the response body (`r2/build:298-303`).

**Cause:** `payload_digest` on `save_attempt` is the POST body; the recorded outcome digest is unrelated (hash of `booking_id`). Binding of “this HTTP response” to the planned effect is weaker than r2.

**Severity:** low. **Class:** application defect.

A second *different* request id for the same attempt is not issued. A second POST of the *same* id is issued on retry after 404, which the brief requires (R9).

## 5. Error and unknown outcomes

Carrier path: fetch throw, empty/non-JSON body, HTTP 500, and non-200/non-404 lookup become `unavailable` and leave `attempt_saved`. They do not confirm `booked` from a timeout. r1 `provider` `278-316`; r2 `httpJson` `243-264`. Dropped-reply tests in each replica’s `desk.test.mjs` assert `unavailable` then reconcile `booked` with one effect.

GET 404 is the only `not_sent` path (r1 `cmdReconcile` `553-554`; r2 `555-557`). Stub contract returns JSON `{"error":"not_found"}` for 404, so r1’s `if (!json) unavailable` does not misfire against this stub.

**F12 (low).** r1 `cmdReconcile` treats any `request_id` as reconcilable, not only `attempt_saved` (`543-548`). A non-booked row with a leftover id would GET. Not observed on the happy machine (id is written only in `save_attempt`).

**F13 (low).** r2 `cmdPack` maps every non-picked leftover state to `expired` (`r2/build:423`). Wrong code, still a refusal.

Unknown order/facility: r2 maps `StoreNotFoundError` and `classify === not_found` (`86-89`). r1 maps only `not_found` (`84-86`); a raw store miss would fall through to `unavailable` (`602-606`). Single shared store makes that less likely.

## 6. Persisted owner routing (change stage)

Guidance: keep v1 loadable; route by `aggregate.owner`; do not command an old aggregate through the new machine (`docs/machine-evolution.md`, `skills/ikaros/change.md` step 5a).

### r1/change — routes by owner; show-through-v2 then re-show on owner

`ordersMachine` (`src/desk.mjs:155-158`) returns v2 iff `ctx.ordersV2.identity.equals(agg.owner)`, else v1. `showOrder` (`169-175`) may `show` via v2 first (allowed for reading owner) then `machine.show` on the owner.

**Observed** (build `./run` created packed `o1`, then change `./run` against the same `STATE_DIR`):

- `status` → packed, v1 owner `{machine_id: warehouse_order, version: 1, spec_hash: 9d8442f68be1bf52…}`
- `unpack o1` → `{"error":"picked"}` (identity check `522`; does **not** execute v2 `unpack`)
- `cancel o1` → `{"error":"not_picked"}` (v1 packed keeps original refusal)
- new `o2` packed cancel → `cancelled` via `cancel_live`

**F14 (low).** v1 packed `unpack` uses error `picked` rather than a dedicated refusal. Still a refusal; no v2 command on the v1 aggregate.

**F15 (medium, continuity gap in tests).** r1/change `test/desk.test.mjs` never creates a v1 instance with the pre-change binary. Owner routing works (reproduced) but is untested in-repo.

**F16 (low).** In-flight `aux.pending` `create_order` recovered after the change always `createWith` on v2 (`266-279`), so a create that started on v1 can be born as v2.

### r2/change — routes by owner; same observed behavior

`isV2` / `loadOrder` (`169-171`, `389-400`). If v2 `show` returns a non-v2 owner, it re-shows via v1.

**Observed:** v1 packed `unpack` → `picked`; v1 packed `cancel` → `not_picked`; new v2 packed `cancel` → `cancelled`.

**F17 (low).** Fallback `return { machine: orderV1, order: viaV2 }` (`395`) could pair a v1 machine with a v2-shown aggregate if v1 `show` fails. Not hit in the continuity run.

Neither change replica commands a v1 packed order through v2 `unpack` / `cancel_packed` / `cancel_live`.

## 7. Hollow paths / unused rules / weak tests

### F18. r2/change test named packed-cancel does not cancel packed

**Where:** `tests/desk.test.mjs:239-271` (`"consolidated parcels, unpack, packed cancel atomic"`).

**Cause:** The test unpacks, packs, books, then asserts `cancel` is `cancel_open`. It never cancels a packed unbooked order (CHANGE C4). Inherited build test still expects packed cancel → `not_picked` (`tests/desk.test.mjs` “expire before book and cancel packed”).

**Severity:** medium (false coverage). **Class:** application defect (test).

### F19. Corpora are type-valid placeholders

r1 `machines/*.ik.cases.json` and r2 `order.ik.cases.json` are single `ok` rows per command (`build.md` step 10: starter corpora usually witness nothing). Scenarios (`scenarios/order-book.json`, `book.json`, `order-unpack.json`) walk the happy command sequence only; they are not hollow assertions, but they do not cover crash/saga seams.

### F20. r1 order machine does not guard the deadline

`machines/order.ik.toml` `pack` (`30-35`) and `expire_live` (`41-43`) have no `now_ms` `when`. Host `maybeExpire` is the deadline authority. Public `./run pack o1` with `NOW_MS=50` on deadline 50 did expire (host path). A one-line skip of `maybeExpire` in `cmdPack` would let the machine pack after the deadline.

r2 passes `now_ms` into `pack` / `expire` (`when = "$now_ms < pickup_deadline_ms"`). That is the Ikaros-shaped version.

**Severity:** medium. **Class:** application defect (host status branch); r2 shows the brief can be expressed on the machine.

### F21. r1/change `cancel_live` from packed is real; r1/build `pack` from packed is host-short-circuited

Not unused. r1 parcel `keep` is used in recover. r2 `invariants.booked_has_ids` is machine-only (not a host hollow).

No command was found that returns exit 0 without a runtime commit on the happy path, except reads (`status`, `facility-status`, idempotent repeats that `show` and exit).

## 8. Disposable shadow-state check

What single edit would keep the happy path appearing to work while bypassing the runtime:

**r1 (build and change).** Delete the `expire_live` call in `maybeExpire` (r1/build `src/desk.mjs:267`; r1/change `330`). `writeAux` + `finishFree` already free parcels from the sidecar. Observed F1 is that same split without any edit: the sidecar is sufficient to mutate capacity while the order row stays `picked`. That is the disposable shadow.

**r2 (build and change).** Occupancy meaning is already host-side. Replacing `facility.execute({name:"hold"|"release", ...})` with a sibling JSON file and reading it in `occupancyOf` would leave the order machine in place and still enforce exclusivity on the happy path. A smaller lie: skip `execute("cancel_picked")` and only `releaseParcel` — cancel would not look cancelled on restart, so that does *not* keep working. The occupancy blob is the bypass that survives.
