# Desmo v0.3 — update set

Status: design, not implemented. Basis: source at `5685254` (v0.2.1; `origin/main` `e305cfa` only moves `LATEST_RELEASE`),
the Datadog `reflex` SDK, and `ATS-IK-BOUND-DECISION-AX-02` (REQ-AX-026..035).

## 0. Principle

One authority path (`decide` → `apply` → `Store` transaction → journal/projection). One forward version.
Transports (one-shot, session, batch) and surfaces (describe, dry_run, explain, effect runner) are views over that path,
never alternate implementations. Strict runtime-version equality is kept: `ik`, Python client and worker ship in lockstep
(`0.3.0`, protocol `1.1`). Consumers pin an artifact; rollback is the previous pin. Schema stays `3`; no store migration.

## 1. Round 1 — where the time actually goes (measured, not assumed)

Profiled `ranger lab run --steps 2` (composition fixture): wall 6.1 s, 22 journal events.

| Cost | Measured | Per run |
|---|---|---|
| `ik` process spawn | 1.1 ms | ~25 × → negligible |
| `ps eww -axo` tree scan (success path) | 2.9 ms (69 procs) | ~75 × → ~0.2 s |
| Python worker interpreter + reducer import (`-I`, fresh process) | **93 ms** | ≥ 44 × (22 decide + 22 apply) → **~4.1 s** |

`ExternalMachine::invoke` (`src/external.rs`) calls `run_process` for **every** `decide` and **every** `apply`; the worker
re-imports the reducer (`load_reducer`) each time. `verify`/`replay` fold every event through `apply`, so they cost one
interpreter per event. This is the dominant cost (~70 % of wall). My earlier plan ranked persistent `ik --session` first;
that was wrong — session reuse alone removes ~1 ms spawns and leaves the 93 ms worker spawns untouched.

Known second-order quadratic: each `decide`/`apply` ships the full aggregate state over JSON and the kernel re-canonicalizes,
digests and persists the full projection per commit ⇒ O(N · |state|) bytes per run. Not fixed in v0.3; v0.3 *measures* it
(U5) so a delta/fold protocol (v0.4) is decided from data.

## 2. Round 2 — adversarial stress of the naive design

1. **Persistent session without persistent worker** — no gain (above). Order: worker first.
2. **Persistent worker breaks the purity contract** if reducer modules keep mutable module state across calls. Mitigations:
   worker is stateless by construction (state arrives per request; `freeze`/`thaw` already enforced); `code_digest` verified at
   worker start; worker is recycled after any diagnostic, exception, timeout, or `N` calls; `IK_REDUCER_PARANOID=1` runs a
   sampled cross-check against a fresh worker and fails closed on divergence; documented as contract, not sandbox.
3. **Per-call timeout/leak safety** currently relies on killing the tree after every call. With a long-lived worker the
   process-tree scan moves to the cold path (timeout, crash, session close, `ik` exit); the worker already runs in its own
   process group (`setpgid`), and the `ik` child gets parent-death termination so a killed `ik` cannot orphan a worker.
4. **Batch capability chaining**: the host cannot know the next nonce. The kernel threads the capability internally; only the
   *first* command is checked for staleness (identical to today), later commands are checked against the in-transaction
   successor. The response returns the final capability.
5. **Batch must not cross an external boundary.** Rule is structural, not name-based (the kernel does not know command names):
   a batch is a prefix of commands in which **only the last may emit an effect intent**; `record` is a separate op and is
   rejected inside a batch (`IK_BATCH_EXTERNAL_BOUNDARY`). All-or-nothing: one `BEGIN IMMEDIATE`, N journal rows, one commit;
   any decide/apply failure (including worker crash) rolls back all rows and reports `failed_index`.
6. **Idempotence/duplicates**: a batch is not retried by the transport. Lost reply ⇒ host reconciles via `show` (existing
   behaviour); `SubmissionUnknown` stays the host's disposition (AX-02 REQ-BD-016).
7. **Session crash** mid-request leaves SQLite at the last committed transaction (WAL); no new recovery logic.
8. **Strict `deny_unknown_fields` envelope**: new ops/fields are additive only inside protocol `1.1`; unknown ops still fail closed.

## 3. Round 3 — agent-experience surface (Reflex + AX-02)

What Reflex gets right and what maps to Desmo without adopting its executor:

| Reflex idea | Desmo v0.3 mapping |
|---|---|
| Guards/invariants evaluated at execution time against current state | Already `decide`/`apply`. Add optional reducer `invariants(state)` evaluated in the same worker call after `apply` → `IK_INVARIANT_FAILED` (no extra round trip). |
| `evaluation_error` is a first-class typed input, so failures are transitions | Pattern + docs for reducers; no kernel change. |
| Rejection reason surfaced per decision (`reflex.transitions` w/ reason) | Every response carries a structured `disposition` (below). |
| Per-decision provenance, not a "latest response" slot | Provenance rides in each response/receipt; no shared mutable slot (AX-02 S08). |
| Early invalid-combination checks (macro) | `ik check` for Python reducers: command-schema ↔ handler ↔ effect-completion consistency, before dispatch. |
| Typed Judge/Controller separation | Out of kernel scope; stays in the host adapter (AX-02 §3). |

Additive surfaces (all read-only or transport-only; none mints authority):

- `disposition` on every response: `{status, native_code, rule, commitment: yes|no|unknown, effect_status: none|pending|recorded|unknown,
  next_action: <domain-derived>|UNKNOWN, prohibited: [...]}`. Stale refusal never suggests "refresh and resubmit" (AX-029).
- `describe` op / `Machine.describe_commands()`: declared command names + argument schemas + effect kinds; applicability is
  `unknown` unless derivable; never a capability (AX-032).
- `dry_run` op: runs `decide` on the current projection with **no commit, no capability consumption**; returns the would-be
  decision/refusal rule, explicitly non-authoritative. This is the Desmo analogue of Reflex guard visibility and the cheapest
  large AX win.
- `explain` op: read-only assembly of journal, receipts, effect intent/outcome, and unresolved fields (AX-033).
- Python `EffectRunner.run(pending, handler)` / `continue_(saved)`: carries exact `EffectIntentV1` binding into
  recording; reuses a saved exact outcome without re-running the handler; unknown stays unknown; no auto-retry (AX-030/031).
- `timing` block on every response: `{decide_ms, apply_ms, commit_ms, worker_calls, bytes_in, bytes_out}` + optional
  `--trace <jsonl>`; this is what makes the quadratic question answerable.

## 4. Round 4 — the cohesive v0.3.0 set and its order

Each unit ships behind the same dispatch path, is independently measurable, and has a gate.

| # | Unit | Change | Gate |
|---|---|---|---|
| U1 | **Persistent reducer worker** | Rust `ExternalMachine` holds a long-lived worker over line-delimited stdio; worker `serve` loop; recycle rules; paranoid mode | Same events/state digests as v0.2.1 on the fixture; 2-step run ≥ 3× faster (est. 6.1 s → ~1.7 s) |
| U2 | **Cold-path cleanup** | Drop per-call `ps` scan (Rust + Python); keep on timeout/crash/close; pdeathsig | No orphan worker after kill -9 of `ik` (test) |
| U3 | **`ik --session`** | Line-protocol loop; reducer registered once; one `Store` open; Python `Session` (context-managed, no implicit retry) | one-shot and session produce byte-identical journal hashes |
| U4 | **Structural `batch`** | Prefix-with-effect-last rule; capability chaining; atomic rollback | failed batch leaves 0 rows; success emits ordered events; `record` in batch refused |
| U5 | **Timing/trace** | `timing` block + JSONL trace | bytes/command reported for the Ranger run |
| U6 | **Disposition + describe + dry_run + explain** | per §3 | AX-T18/T21/T22 scenarios; dry_run changes no generation/journal/effect |
| U7 | **EffectRunner + `ik check` (Python)** | per §3 | AX-T17/T19/T20; mismatch fails before dispatch |
| U8 | **Ranger adoption** | `ResearchHost(ik_session=True)`, batch `[CommitAllocation, CapturePolicyFrame, PlanExperiment]`, lazy imports in `ranger.ikaros_loop.reducer` | canonical CLI test < 15 s; full suite unchanged |

Non-goals (carry over from AX-02): no new DSL, executor, scheduler, schema change, auth, or exactly-once claim; no change to
capability/currentness/effect/replay laws; helpers that merely hide a semantic failure are disqualified (AX-035).

## 7. Resolved decisions and "don't reinvent" corrections

Decisions (owner): (1) lockstep upgrade — yes; (2) paranoid purity check default-off — yes; (3) state delta — folded
in only as far as a canonical solution exists (below); (4) ship all units together as one `0.3.0` — yes.

**Decision 3, with data.** After the profiled 22-event run the aggregate state is 13.9 KB and the whole journal 41 KB
(events already carry deltas since 0.2.0). Shipping state both ways for ~44 calls is ~0.4 MB of JSON — milliseconds — against
~4 s of worker spawns. A bespoke wire-delta protocol would cut a non-dominant cost by ≤ 2× and add a new divergence surface
between the worker's resident state and the kernel's authoritative state. The canonical cure for O(N·|state|) *persistence*
is event sourcing with snapshot cadence (store events; snapshot every K), which is a schema change (`schema 4`), not a wire
trick. So v0.3 ships U5 (bytes/command) and the decision to move to snapshot cadence is made from that data. If a wire delta is
ever needed, it is RFC 6902 JSON Patch, not a custom format.

**Use the standard, not our own variant:**

| Need | Canonical solution | Consequence for the plan |
|---|---|---|
| Long-lived out-of-process reducer | The language-server pattern: persistent child, JSON-RPC 2.0 | Worker protocol becomes **JSON-RPC 2.0, newline-delimited over stdio** (the MCP stdio convention). `decide`/`apply`/`describe` are methods; errors are JSON-RPC error objects whose `data` is the existing `{code, rule, message}` diagnostic. |
| Session framing for `ik` | Same JSON-RPC 2.0 / ndjson framing | `ik --session` speaks the same framing as the worker; one parser per language. |
| Atomic multi-command | A database transaction (SQLite `BEGIN IMMEDIATE` … `COMMIT`) | Name it `transaction`, not `batch`: JSON-RPC "batch" means independent requests with no atomicity. |
| Child lifetime / orphan safety | POSIX process groups + `PR_SET_PDEATHSIG`; terminate on EOF of stdin | Replaces per-call `ps` scans; scan kept only on timeout/crash. |
| Command/argument schemas for `describe` | JSON Schema 2020-12 | Reducers declare schemas in JSON Schema; no bespoke schema language. |
| Persistence at scale | Event sourcing + snapshots | Deferred to schema 4 (data-gated). |
| Wire delta (if ever) | RFC 6902 JSON Patch | Not in 0.3. |

Dependency policy is unchanged: the Python package stays stdlib-only and the Rust crate keeps its current dependency set;
we adopt standards at the *protocol* level instead of pulling in server frameworks (`jsonrpsee`, `pygls`) whose async/network
assumptions do not fit a one-process-per-aggregate-store synchronous loop.
